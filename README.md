# HUBProxy

Прокси Telegram, который снаружи выглядит обычным сайтом. Одна команда, один порт 443.

```bash
bash <(curl -sL https://raw.githubusercontent.com/qwe8nxtroud/hubproxy/main/install.sh) proxy.example.com
```

В конце скрипт выдаёт готовую ссылку `tg://proxy?...` — открываете её на телефоне, Telegram сам предлагает подключиться.

## Как устроено

```
Caddy :443 (TLS) ──► TProxy ──┬── браузер  → страница «Технические работы»
                              └── Telegram → MTProxy (только localhost)
```

Провайдер видит одно: HTTPS-запросы к веб-серверу на стандартном порту. Кто именно пришёл — человек с браузером или клиент Telegram — разбирает TProxy уже внутри, после расшифровки TLS.

Открыть домен в браузере может кто угодно, включая проверяющего: он увидит обычную страницу обслуживания, без единого намёка на прокси.

## Что ставится

| Компонент | Роль |
|---|---|
| **Caddy** | держит 443, сам получает и продлевает сертификат Let's Encrypt |
| **TProxy** ([telegramdesktop/tproxy-server](https://github.com/telegramdesktop/tproxy-server)) | делит трафик: сайт или Telegram |
| **MTProxy** ([TelegramMessenger/MTProxy](https://github.com/TelegramMessenger/MTProxy)) | сам прокси, слушает только localhost |

## Требования

- Ubuntu или Debian, root
- домен с A-записью на этот сервер
- свободный порт 443

Если домен за Cloudflare — на время установки отключите проксирование (оранжевое облако). Let's Encrypt должен достучаться до сервера напрямую.

## Чем отличается от аналогов

**Проверяет условия до начала работы.** Домен не резолвится на этот сервер или 443 занят — скрипт скажет об этом сразу и не станет полчаса ставить то, что всё равно не заработает.

**Повторный запуск ничего не ломает.** Запустили второй раз — увидите текущие данные подключения, а не сломанную установку.

**Проверяет результат по факту.** В конце реально запрашивает домен по HTTPS и смотрит, слушают ли службы свои порты, — а не рапортует об успехе по коду возврата.

**Удаляется одной командой:**

```bash
bash <(curl -sL .../install.sh) --uninstall
```

**MTProxy привязан к localhost.** Наружу торчит только 443. Прокси нельзя использовать в обход маскировки, даже зная порт.

## Управление

```bash
# сменить секрет (старая ссылка перестанет работать)
bash install.sh proxy.example.com --rotate

# данные подключения
cat /etc/hubproxy/connection.txt

# журналы
journalctl -u hubproxy-tproxy -n 50
journalctl -u hubproxy-mtproto -n 50
```

## Что проверено

Установка целиком прогнана на чистой Ubuntu 26.04 (2 ядра, 2 ГБ): все компоненты собираются, сертификат выпускается, домен отдаёт страницу-заглушку, службы поднимаются и слушают положенные порты, MTProxy не виден снаружи.

Подключение живого аккаунта Telegram проверяйте у себя — оно зависит от вашей сети и клиента.
